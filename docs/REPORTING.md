# Reporting rules for coding agents

These rules apply to every coding agent working in this repository: Codex, Claude, Gemini,
Mistral, GLM and any other. They keep generated analysis out of Git and keep the permanent
documentation in [`docs/`](README.md) accurate.

## The two kinds of documentation

| | Permanent documentation | Agent reports |
|---|---|---|
| Location | `docs/` (see [README.md](README.md)), plus `README.md`, `CHANGELOG.md`, `VERSIONS.md` and the folder READMEs | `docs/_reports/` only |
| Git | Tracked and published | Ignored by `.gitignore` (`docs/_reports/`) |
| Content | The current project: architecture, guides, behavior, procedures | One-off output: audits, benchmarks, investigations, validation runs, release verification, refactoring records |
| Lifetime | Maintained as the project changes | A record of a moment; never edited to describe the present |

## Rules

1. **Generated reports go into `docs/_reports/`.** Nothing generated by an agent run goes
   anywhere else in `docs/`.
2. **Choose the correct category** (table below) for each report.
3. **New categories are allowed** when no existing one fits. Create a new lowercase kebab-case
   directory under `_reports/`; do not stretch an unrelated category.
4. **Never create temporary or report files directly inside `docs/`** or its permanent
   subdirectories.
5. **Never overwrite permanent documentation with generated analysis.** A report about a
   subsystem does not replace that subsystem's document.
6. **Use descriptive, consistent filenames** (see [Naming](#naming)).
7. **Use Markdown for text.** Use JSON, CSV or recordings only for data that is not prose, and
   keep that data beside its report.
8. **Include context, findings, validation and limitations** where relevant: what was asked,
   on which branch and commit, what was found, how it was checked, and what remains uncertain.
9. **Keep report output separate from source code.** Reports, scratch data and benchmark
   results never go under `src/`, `bin/` or `scripts/`.
10. **Never force-add ignored reports** (`git add -f`). If a report must be shared, share the
    file directly.
11. **Change permanent documentation deliberately and accurately.** Verify statements against
    the current code. When a report reveals something lasting (a new invariant, a changed
    workflow, a corrected behavior), summarize it in the matching permanent document. Keep
    the original report; do not commit it.
12. **Prefer updating an existing document** to creating a new one on the same subject, for
    both permanent docs and reports (for example, a follow-up run updates its report or adds a
    dated sibling, not an unrelated new file).

## Categories

| Directory | Use for |
|---|---|
| `_reports/audits/` | Code, architecture, test or dependency audits |
| `_reports/performance/` | Benchmark runs, profiles and performance analyses; their JSON data in a same-named folder |
| `_reports/refactoring/` | Records of refactors: scope, changes, compatibility checks |
| `_reports/reliability/` | Provider or subsystem reliability repairs and regression analyses |
| `_reports/release-verification/` | Pre-release verification output for a version |
| `_reports/investigations/` | Debugging, root-cause work, task plans and one-off records |
| `_reports/recordings/` | Terminal recordings and screenshots that support a report rather than permanent docs |
| `_reports/archive/` | Superseded permanent documents kept for reference after consolidation |

## Naming

- **Format:** lowercase kebab-case `.md`, named for the subject first:
  `<subject>[-<qualifier>]-<kind>.md`.
- **Dates:** add an ISO date (`-YYYY-MM-DD`) when the same kind of report may be repeated:
  - `core-quality-audit-2026-10-17.md`
  - `terminal-renderer-audit-2026-11-02.md`
- **Phases and versions:** use the phase or version as written:
  - `phase-1-performance-analysis.md`
  - `phase-1.1-validation.md`
  - `release-0.1.19-verification.md`
- **Investigations:** name the problem, not the agent:
  - `provider-switching-investigation.md`
  - `google-antigravity-regression-repair.md`
- **Data:** files that belong to a report sit in a folder with the same stem:
  `performance/phase-1.1/baseline/*.json` beside `performance/phase-1.1-runtime-efficiency-report.md`.
- **Avoid:** agent names, `FINAL`, `NEW`, `v2` and all-caps names. Use a dated sibling instead.

## Git behavior

- `.gitignore` contains `docs/_reports/`, so new reports and categories never appear in
  `git status`.
- Check with `git check-ignore -v docs/_reports/<category>/<file>.md`.
- The index must contain nothing under `docs/_reports/`: `git ls-files docs/_reports` prints
  nothing.
- Ignoring and untracking does not erase history. Reports that were committed before this
  policy, such as the earlier audits and release-verification files, remain in past commits.
- A fresh clone has no reports. Permanent documentation must therefore never link to files
  under `_reports/`.
